4. 결과는 데이터의 구조에 크게 의존한다. 콘크리트·factory에서 박스 크기와 desirability가 균일해서 아이디어 2·3이 무력했다. 반응이 2개인 Naval에서는 desirability를 반영하는 방식이 이겼다.

## 1. 공통 기준선: 원논문 파이프라인

모든 아이디어는 같은 기준선에서 출발한다.

1. **박스 생성**: MRS-PRIM(peeling ratio α = 0.05, min_support = 100, 변수 부분집합 S개를 무작위로 골라 반복 peeling). DRS-PRIM은 MSE = (평균 − 목표)² + 분산을 최소화한다.
2. **유사도**: 경험적 Jaccard = |교집합| / |합집합|.
3. **군집화**: average-linkage 계층적 군집화.
4. **선택**: N_Memb(5–10) × K 완전 격자탐색에서 ρ_eff ≥ 0.6 제약 하에 ECC(효과적 클러스터의 평균 조밀도)를 최대화하는 (N_Memb\*, K\*) 채택.

**데이터셋**

| 데이터 | 규모 | 반응 | desirability |
|---|---|---|---|
| Concrete | 1,030행, 입력 8 | 1개 (압축강도) | NTB (목표 60 MPa) |
| Factory | 14,088행, 입력 41 | 15개 | NTB (자동 목표) |
| Naval Propulsion | 11,934행, 입력 14 (상수 2개 제외) | 2개 (압축기·터빈 감쇠계수) | LTB, 기하평균 |
| 원논문 제철 | – | 2개 | NTB (비교 참고용, 데이터 미포함) |

**검증 원칙** (아이디어 1·6에서 확립)

- confirmation 데이터는 선택이 끝난 뒤 1회만 사용한다.
- 선택 파라미터(예: RATIO2)는 inner validation에서만 결정한다.
- N_Memb를 임의 고정하지 않고 5–10 전체를 탐색한다.
- 최대 클러스터 1개가 아니라 전체 클러스터의 training 크기 가중평균 채점을 병행한다.
- 단일 분할이 아니라 여러 분할(시드)로 반복검증한다.

## 2. 아이디어별 최종 베이스라인

### Idea 1 — 정밀 레시피 수축 알고리즘

**문제**: 효과적 클러스터는 여전히 여러 subregion으로 파편화되어 있어, 엔지니어가 적용할 단일 운전 범위가 불명확하다.

**구조**: 1단계 통합 경계(멤버 박스의 변수별 min/max) → 2단계 빈 공간 편입 품질 리스크 평가 → 3단계 경계 수축.

**두 구현과 최종 선택**

| | 방법 A | 방법 B (최종 채택) |
|---|---|---|
| 수축 방식 | 몬테카를로 가상포인트 + KNN(k=10) 대리모델, 중첩 밀도(v3)로 깎을 경계 결정 | 통합박스 안의 실측 데이터만으로 PRIM을 한 번 더 수행 |
| 종료 | ΔD ≤ ε (V_min 제거, MAX_ITER 스윕) | min_support2 = max(20, n_box × RATIO2) |
| 장점 | 평균 개선폭·confirmation 성능이 더 높음 | confirmation 표본 수가 일관되게 안정적, 빠름, PRIM 철학과 일치 |
| 단점 | 표본이 작아지고 종료가 부피·잔존비율 조건에 쏠림 | 성능 수치는 A보다 낮음 |

**최종 절차**

- 클러스터 선정: N_Memb(5–10) × K 완전탐색. Concrete에서 N_Memb\* = 5, K\* = 650.
- 수축 방향 결정: v3(가상포인트가 멤버 박스에 다차원으로 동시에 속하는 비율)이 v1(대리모델 예측)보다 개선폭이 2배 이상 크다(+0.186 vs +0.081). 단, n_conf는 작아진다.
- 대리모델 4종(RF, GBM, KNN, Ridge)은 V_min이 먼저 발동해 결과가 동일했다. V_min을 제거하면 KNN만 자연 종료했다. KNN 채택 근거는 정확도 우위가 아니라 자연 종료 가능성이다.
- 방법 A와 B 중 표본 신뢰도와 PRIM 철학을 중시하면 B를, 성능 수치를 중시하면 A를 택한다(트레이드오프).

**후속 보정 (nested hold-out)**

| 데이터 구간 | 역할 |
|---|---|
| Outer training (Concrete 721) | 방법 개발 전체 |
| Inner training (504) | candidate box와 cluster 생성 |
| Inner validation (217) | RATIO2 선택에만 사용 |
| Outer confirmation (309) | 선택 후 최종 평가 1회 |

- Safeguard: 수축 후 통합박스당 평균 관측치 ≥ 25이고, 수축 전의 50% 이상이면 우선 채택한다. 후보가 없으면 관측치를 가장 많이 보존하는 후보를 쓴다.
- Concrete의 inner MIN_SUPPORT는 50·75·100 비교 후 75를 사용했다.
- **주의**: 기존 보고서의 개선폭은 개발 탐색 결과로는 유효하다. 하지만 RATIO2를 같은 데이터로 골랐으므로 누수 없는 최종 성능으로 인용해서는 안 된다. nested 절차의 수치는 실행·저장된 결과만 별도로 보고해야 한다.

**근거 파일**: `idea1/idea1_master_v3.py`, `idea1/idea1_ratio2_sweep.py`, `idea1/idea1_nested_prim_factory.py`, `idea1/idea1_nested_prim_naval.py`, `idea1/idea1_final_report.docx`, `idea1/idea1_methodA_methodB_full.docx`

### Idea 2 — Tversky 유사도

**동기**: 작은 박스가 큰 박스에 완전히 포함되어도 Jaccard는 거리를 크게 잡는다. Tversky는 큰 박스에만 있는 부분에 낮은 가중치(β = W_LARGE)를 준다. 쌍마다 작은/큰 박스를 판별하므로 대칭성 d(A,B) = d(B,A)는 자동으로 만족한다.

| 실험 | 조건 | 결과 |
|---|---|---|
| 1차 | Concrete 표준 | support 100–119(1.19배), 비대칭 포함 쌍 0건 |
| 2차 | Factory(14배 규모) | support 250–263, 0건, Jaccard와 Tversky의 ECC 동일 |
| 3차 | 다단계 min_support로 비대칭 유발 | W_LARGE = 0에서 ECC 0.97 → 0.16으로 붕괴. 최적 0.6–0.8에서도 +0.0009 |
| 4차 | 비대칭 없는 표준에서 재스윕 | 개선 없음. W_LARGE = 0은 −0.0195 |
| 5차 | min_support 100 → 2 | 크기 다양성은 1.13배 → 2.50배로 증가하나 D > 0.95 박스가 0% → 2.2%로 늘어 신뢰도 훼손 |
| Naval | 같은 박스에서 Jaccard와 Tversky만 교체 | ECC 0.9783 vs 0.9769. Tversky가 0.0014 낮음. 이 수치는 CSV로 저장되지 않았다. |

**최종 베이스라인**: 원논문 Jaccard 유지. 원인은 MRS-PRIM의 patient peeling이 박스 크기를 거의 같게 만드는 구조다. min_support = 100은 신뢰도를 지키는 정당한 설계다.

**근거 파일**: `idea2/idea2_final_report.docx`, `idea2/idea2_weight_sweep.py`, `idea2/idea2_naval_compare.py`

### Idea 3 — 신뢰도 가중 클러스터링

**정의**: 신뢰도 R = √(D̃ · S̃) (정규화한 desirability와 support의 기하평균). 신뢰도를 박스 간 거리의 분모에 넣어 신뢰도가 높을수록 거리가 짧아지게 한다. γ는 반영 강도이며 γ = 0이면 원논문과 동일하다.

| 실험 | 조건 | 결과 |
|---|---|---|
| 1차 | 표준, γ = 1 | CV: desirability 0.021, support 0.022. ECC 0.9502 → 0.9275 (−0.0227) |
| 2차 | 인위적 크기 다양화 (CV 0.124, 0.887) | γ = 0.25에서만 +0.0014. γ = 1에서 −0.0143 |
| 3차 | 표준에서 γ 0–1 정밀 스윕 | γ = 0이 항상 최선 (γ = 1에서 −0.0313) |

**최종 베이스라인**: γ = 0 (가중 없음). 표준 박스는 품질 편차가 2% 수준이라 가중치가 구별할 신호가 없고, 차별을 두면 노이즈로 작용한다. 이 아이디어는 중단한다. 다른 결합 방식(가중합·조화평균)이나 다중반응 데이터는 검증하지 못했다.

**근거 파일**: `idea3/idea3_final_report.docx`, `idea3/idea3_optimized.py`

### Idea 4 — 합성 데이터 기반 정답 복원 검증

**목적**: 정답(고성능 영역의 개수·위치)을 아는 합성 데이터로 4단계 파이프라인이 정답을 복원하는지 검증한다.

**버전 진행**

| 차수 | 변경 | 결과·판단 |
|---|---|---|
| 1차 | X 독립 균등분포, D는 가우시안 봉우리 | 출발점 |
| 2차 | Gaussian copula로 상관구조 보존 | Age가 비현실 값(25개 고유값 vs 실제 14개), 레시피 반복 구조 미재현 |
| 3차 | Smoothed bootstrap + recipe-replicate | 14개 Age 값 보존, 레시피 반복 구조 재현(489/1200, 평균 2.45회) |
| 4차 | 무작위 시드 반복 | 실행 시간 과다로 폐기 |
| 5차 | 고정 시드 G-스윕 + 정답별 recall·precision·F1 | N_eff가 G(2–8)와 무관하게 35–45. 평균 F1 0.270 ± 0.099, 개수 일치 0/7 |
| 6차 | 실측 1,030개로 학습한 RSM(R² = 0.811)을 desirability로 사용 | G를 바꿔도 K\*, ECC, N_eff 동일 |

**6차 결과의 해석 보정 (후속 연구)**

- G를 2·3·5로 바꿔도 입력 X, RSM 예측 D, pipeline seed는 같고 정답 label 수만 달라진다. 따라서 결과가 동일한 것은 자연스럽다.
- 여러 D = 1 지점은 독립 봉우리의 증거가 아니라 RSM(x) = 60을 만족하는 넓은 level set일 수 있다.
- 처음에는 "연속 능선(ridge)"으로 해석했다. 그러나 k-NN graph에 직선 보간 경로 조건을 넣은 연결성 검사에서 336/336 조합(원 RSM 16 + bootstrap 320)이 "단일 연결 영역 미지지"였다. 그렇다고 연속 공간이 수학적으로 불연결이라는 증명은 아니다.

**통제 위상 실험** (같은 X, 같은 잡음, pipeline seed 0–4)

| 지표 | 연결 정답 1개 | 분리 정답 3개 |
|---|---|---|
| 평균 N_eff | 47.0 | 46.4 |
| 정답 개수 일치율 | 0% | 0% |
| 1:1 복원률 | 0% | 0% |
| 평균 over-split factor | 47.0배 | 15.47배 |
| 평균 cluster purity | 0.925 | 0.326 |
| component union coverage | 0.601 | 0.372 |
| best-cluster coverage | 0.294 | 0.347 |

- 연결 영역은 과분할된다(1개 영역 → 45–48개 조각, 최고 조각이 정답의 약 29%만 덮음).
- 분리 영역은 과분할과 혼합이 함께 나타난다(모든 effective cluster가 세 정답 component와 모두 겹침).

**X 생성 충실도**: zero-inflation 방향 보존(Slag 45.7% → 42.1% 등), Age 고유값 14개 일치, 상관 Frobenius 거리 1.019, D > 0.9 개수 65 vs 60.

**최종 베이스라인**: 3차 X 생성(recipe-replicate) + 6차 RSM desirability + 통제 위상 실험(연결/분리)을 검증 표준으로 삼는다. N_eff는 독립 최적 영역 수가 아니라 stochastic box의 안정적 분절 정도에 가깝다.

### Idea 5 — 콘크리트 DRS-PRIM 사례

**목적**: 제철(MRO) 한 사례로 보인 프레임워크가 DRO 문제에서도 작동함을 보인다. `논문 제안서.docx`의 두 번째 사례 연구 항목에 해당한다. 이전에는 보고서가 없었기 때문에, 이번에 `idea5/idea5_dro_concrete.py`를 다시 실행해 결과를 확보했다(14.7초, 저장: `integrated/results/idea5_run_output.txt`).

**설정** (Koo et al. 콘크리트 DRO 실험과 동일): MSE 최소화, 목표 60, α = 0.05, min_support = 130, S ∈ {5, 6, 7}, 크기당 300 trial(총 900).

**결과**

| 항목 | 값 |
|---|---|
| 생성 박스 | 900개, support 130–144 |
| 박스 MSE | 최소 125.4, 중앙 136.2, 최대 415.5 |
| 최종 채택 | N_Memb\* = 5, K\* = 265 (N_eff = 46, ECC = 0.9899, ρ_eff = 0.621) |
| 최대 클러스터 | 멤버 71개, 평균 MSE 133.1 |

| N_Memb | K\* | N_eff | ECC | ρ_eff |
|---|---|---|---|---|
| 5 | 265 | 46 | 0.9899 | 0.621 |
| 6 | 225 | 37 | 0.9804 | 0.627 |
| 7 | 205 | 32 | 0.9705 | 0.638 |
| 8 | 205 | 29 | 0.9685 | 0.614 |
| 9 | 185 | 24 | 0.9555 | 0.628 |
| 10 | 185 | 22 | 0.9521 | 0.608 |

**해석과 한계**

- 박스 생성(DRS) → Jaccard → average-linkage → N_Memb × K 탐색이 코드 수정 없이 이어졌다. 프레임워크가 MRS·DRS 어느 박스에도 적용된다는 주장의 근거다.
- 박스 MSE가 125 이상으로 큰 것은 목표 60 MPa가 콘크리트 강도 분포의 상단에 있고, min_support = 130에서는 평균이 목표에 충분히 다가가지 못하기 때문으로 보인다. 이 원인은 이번에 별도로 검증하지 않았다.
- N_eff = 46은 아이디어 4의 관찰(N_eff ≈ 46–47)과 같은 범위다. 여기서도 N_eff를 독립 운전영역 수로 읽으면 안 된다.
- 이번 실행은 단일 시드(SEED_PRIM = 1)이며 hold-out 검증이 없다. "작동함"의 근거일 뿐 성능 우위를 뜻하지 않는다.

**근거 파일**: `idea5/idea5_dro_concrete.py`

### Idea 6 — 민감도 분석 및 목적함수 보완

**원논문의 구조적 문제**: ECC(K)는 거의 단조 증가(0.71 → 1.00)해서 K\*가 내부 최적이 아니라 ρ 제약 경계에서 결정된다. ρ_Limit을 0.45–0.75로 바꾸면 K\*는 크게 움직이지만(0.50에서 800, 0.70에서 450) 상위 1–2위 클러스터의 관측치 집합은 Jaccard 0.95–1.0으로 유지된다. 즉 K\*라는 숫자는 민감하지만 핵심 운전영역은 안정적이다.

**후보 목적함수 결과**

| 후보 | 결과 |
|---|---|
| 방식 0 단순곱셈, 방식 1 가중조화평균, 방식 3 AIC/BIC | 내부 봉우리 형성 성공. 콘크리트에서 원논문 대비 −0.0591, factory에서 ±0 |
| 방식 2 정규화 곱셈 | 실행마다 K\*가 달라 제외 |
| 방식 4 (ECC^a · ρ^b · D̄^c) | 데이터에 따라 상반됨. 콘크리트 10분할에서 평균 −0.0053, 0승 4동률 6패 |
| 후보 1, 4, 5, 9, 11 | 무력화 또는 경계 쏠림. 벌점이 진짜 트레이드오프를 만들지 못함 |

| linkage 변경 | average(원논문)가 최선 |

**L-curve 엘보우** (log ECC – log ρ_eff 곡선의 최대 곡률점, 파라미터 없음)

|---|---|---|---|---|

**검증 절차 보완**: (1) N_Memb = 5 고정 → 5–10 완전탐색, (2) 최대 클러스터 1개 채점 → 전체 클러스터 가중평균 병행(방식 4의 콘크리트 판정이 동률에서 −0.0002로 정정), (3) 단일 분할 → 10분할 반복.

**최종 베이스라인**: 원논문 선택 규칙(ρ_eff ≥ 0.6 하 ECC 최대)을 기본값으로 유지한다. 원논문의 ρ_Limit = 0.6이 데이터의 자연스러운 전환점과 가깝다는 방증이기도 하다. 파라미터를 쓰고 싶지 않다면 L-curve 엘보우가 가장 균형 잡힌 대안이다. 반응이 2개인 MRO 구조에서는 desirability 반영(방식 4·파레토·Borda)이 이득일 수 있다.

## 3. 교차 분석

### 3.1 공통 원인: 박스 균일성

아이디어 2·3은 같은 원인으로 실패했다. MRS-PRIM의 patient peeling은 support 하한까지 계속 깎기 때문에 박스의 support와 desirability가 거의 같아진다(CV ≈ 2%). 박스 사이의 차이를 이용하는 방법(Tversky, 신뢰도 가중)은 이용할 신호가 없다. 박스 이질성이 자연적으로 큰 데이터(min_support 개념이 없는 다른 subregion 알고리즘, 다중반응)에서는 결론이 달라질 수 있다.

### 3.2 공통 원인: 경계해

ECC 단조성 때문에 K\*가 경계에서 결정된다는 문제는 K 축(아이디어 6)뿐 아니라 N_Memb 축에서도 나타났다. 벌점 항을 더하는 시도(후보 5·9·11, N_Memb 지수항)는 극단을 다른 쪽 경계로 옮길 뿐이었다. 파라미터 없는 방식(파레토, Borda, L-curve)이 파라미터 있는 방식보다 반복검증에서 안정적이었다.

### 3.3 지표 해석의 한계

| 지표 | 안전한 해석 | 위험한 해석 |
|---|---|---|
| ECC | 클러스터 내부 박스 유사도 | 정답 영역 복원 성공 |
| N_eff | stochastic box의 분절 정도 | 독립 최적 영역의 개수 |
| K\* | 검증 설정에 민감한 절단 높이 | 고유한 최적 군집 수 |

### 3.4 검증 신뢰도의 계층

같은 방법이라도 검증 설계에 따라 결론이 뒤집혔다.

| 사례 | 약한 검증 | 강한 검증 |
|---|---|---|
| 방식 4 (콘크리트) | 1분할: 동률 | 전체 클러스터 채점: −0.0002, 10분할: −0.0053 |
| Idea 1 개선폭 | RATIO2를 같은 데이터로 선택 | nested hold-out |
| Idea 4 G 스윕 | 정답 개수 일치 여부 | 통제 위상 실험 + 정답별 coverage·purity |

## 4. 산업 적용 시 위험

| 관찰된 한계 | 현장 위험 |
|---|---|
| 연결 영역 과분할 | 허용 가능한 운전·배합 범위를 과도하게 좁혀 유연성을 낮추고 비용을 높인다 |
